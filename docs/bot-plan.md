# План: telegram-бот для tobedone (мульти-юзер)

Публичный бот-ассистент: любой пользователь tobedone привязывает свой аккаунт,
дальше свободный текст в телеге → дешёвая LLM с MCP-инструментами → действия
с задачами. Плюс персональные дайджесты, обзоры и напоминания по расписанию.

## Архитектура

```
Telegram ⇄ бот (Go, long polling)
              ├── sqlite: chat_id → mcp-токен, расписания, отметки напоминаний
              ├── LLM: любой OpenAI-совместимый API (deepseek-chat по умолчанию)
              └── MCP-клиент (streamable HTTP + Bearer per-user) → /mcp
```

Решения и почему так:

- **Мульти-тенантность бесплатна**: MCP-эндпоинт уже скоупит всё по токену,
  бот просто подставляет Bearer конкретного юзера. Один общий `tools/list`
  на всех (инструменты у всех одинаковые).
- **Тот же репозиторий, `cmd/bot/`** — зависимость `modelcontextprotocol/go-sdk`
  уже в go.mod (клиентская часть входит), один `make deploy`.
- **sqlite в volume у бота** — токены, расписания, отметки. В MariaDB не лезем:
  бот остаётся внешним клиентом, весь доступ к задачам — только через MCP.
- **Go + long polling** — вебхук не нужен, наружу ничего не торчит.
  Библиотека: `github.com/go-telegram/bot`.
- **LLM через OpenAI-совместимый endpoint** — DeepSeek, Qwen, GLM, OpenRouter
  выглядят одинаково; провайдер = три переменные окружения.
- **Всё регулярное — без LLM**: дайджесты, обзоры, напоминания и `/today` —
  это `tools/call` + отправка текста. LLM тратится только на свободный текст.
- **Деструктива нет by design**: в MCP нет delete-тула (только create /
  complete / update), так что галлюцинация модели физически не может снести
  задачу. Удаление — только руками в вебе. Так и оставляем.

## Привязка аккаунта

Основной путь — deep link из веба (юзеру не нужно знать слово «токен»):

1. В веб-интерфейсе кнопка «Подключить Telegram» → сервер генерирует одноразовый
   код (256 бит, TTL 10 минут, таблица `link_codes`) и показывает ссылку
   `https://t.me/<bot>?start=<code>`.
2. Юзер тапает, бот получает `/start <code>` и меняет код на постоянный
   API-токен: `POST /api/telegram/exchange {code}` → сервер гасит код и
   выпускает токен с именем «telegram» (обычный `api_tokens`).
3. Бот сохраняет chat_id → токен в sqlite, шлёт короткий онбординг
   («попробуй: добавь купить молоко на завтра»).

Запасной путь для продвинутых: `/link tbd_...` — вставить готовый токен руками.

Отвязка: удаление токена в вебе мгновенно убивает доступ — бот на 401 отвечает
«аккаунт отвязан, жми /start». Симметрично `/unlink` в боте.

## Поток сообщения

1. Незалинкованный чат → только приветствие с инструкцией привязки.
   **Ноль обращений к LLM** — иначе публичный бот станет бесплатным прокси.
2. Команды мимо LLM: `/today`, `/digest`, `/evening`, `/review`, `/tz`,
   `/reset`, `/unlink`, `/help`, для владельца — `/stats`.
3. Остальное — агентный цикл: системный промпт + история чата + сообщение →
   LLM → пока отвечает tool_calls (кап: 6 итераций) — гоняем через MCP с
   Bearer'ом этого юзера → финальный текст (сплит по 4096).
4. История: в памяти, ~20 реплик user/assistant на чат, TTL 30 минут.
   Tool-внутренности в историю не пишем.
5. Лимиты: N LLM-сообщений на юзера в день (env, старт — 50), глобальный
   дневной кап с алертом владельцу.

Системный промпт: сегодняшняя дата + день недели в TZ юзера (критично для
«завтра»), `instructions` с MCP-сервера, «отвечай кратко, после действия —
одной строкой подтверждение».

Мелочи UX: `setMyCommands` при старте (меню команд в интерфейсе телеги),
`sendChatAction: typing` на время LLM-цикла (дешёвые модели небыстрые),
сообщения — plain text или HTML parse_mode (MarkdownV2 с его экранированием
не трогаем).

## Расписания: дайджест, вечерний и недельный обзоры

Одна таблица `schedules (chat_id, kind, weekday, time, board)`, планировщик
раз в минуту проходит по строкам в TZ юзера. Виды:

- **morning** — утренний дайджест: `today_agenda` как есть.
  Команда `/digest 08:30` / `/digest off`.
- **evening** — вечерний обзор: «сегодня сделано: … / на завтра: …».
  Команда `/evening 21:30` / `/evening off`.
- **weekly** — недельный обзор по доске (или по всем): выполнено за неделю +
  что осталось висеть. Команда `/review пятница 19:00 Работа` — можно
  несколько штук. Пример живой конфигурации: в пятницу вечером — по рабочей
  доске, в воскресенье — по личной. Доска резолвится сервером по куску
  названия, как везде.

По умолчанию у новых юзеров всё выключено — сами включают, меньше спама.

## Напоминания к сроку задачи

Раз в ~5 минут бот проходит по привязанным юзерам и спрашивает ближайшие
задачи со сроком; у задач с `due_at` в ближайшем окне — пинг в чат. Отметки
«уже напомнил» — в sqlite (`reminded (chat_id, task_id, due_at)`), чтобы не
дублировать; перенос срока (изменился `due_at`) снова включает напоминание.
Включение: `/remind on|off` (+ v2: «за сколько минут»).

Для этого MCP-тулзам нужен машиночитаемый вывод — см. доработки сервера.

## Доработки на стороне сервера tobedone

Все — маленькие, каждая проверяется тестами как обычно:

1. **Привязка**: таблица `link_codes`, ручка выдачи кода (под сессией),
   ручка обмена кода на токен, кнопка «Подключить Telegram» в вебе.
2. **`parseDue` пошире**: дни недели («пятница»/`friday` → ближайшая будущая)
   и относительные сдвиги (`+3d`). Дешёвой LLM сильно проще передать слово,
   чем посчитать дату; сервер посчитает детерминированно.
3. **Срез выполненных по времени**: аргумент `done_since` в `list_tasks`
   (для вечерних и недельных обзоров).
4. **`structuredContent` в тулзах**: SDK умеет отдавать текст + структуру
   параллельно; текст остаётся для LLM, структура — для кода бота
   (напоминания, потом кнопки). Начать с `today_agenda` и `list_tasks`.

|--------------------|-------------------------------|------------|
| `TELEGRAM_TOKEN`   | из BotFather                  | токен бота |

| `LLM_BASE_URL`     | `https://api.deepseek.com/v1` | OpenAI-совместимый endpoint |
| `LLM_API_KEY`      | …                             | |
| `LLM_MODEL`        | `deepseek-chat`               | |
| `DAILY_LIMIT`      | `50`                          | LLM-сообщений на юзера в день |
| `OWNER_CHAT_ID`    | `123456789`                   | алерты и `/stats` |

Персональное (TZ, времена расписаний, remind on/off) — в sqlite, не в env.

## Надёжность

- **At-most-once**: `update_id` персистится в sqlite до обработки сообщения —
  иначе рестарт бота между получением и обработкой дублирует «купить молоко».
- **Замок на чат**: LLM-цикл занимает секунды; второе сообщение от юзера ждёт
  завершения первого (per-chat mutex), а не запускает гонку.
- **401 от MCP** → «аккаунт отвязан», запись чистится.
- **Наблюдаемость**: лог всех tool-вызовов (кто, что, аргументы, результат/
  ошибка) — когда дешёвая модель начнёт чудить, без этого не разобраться.
  `/stats` владельцу: юзеров всего/активных, LLM-запросов сегодня, ошибок.

## Этапы

1. **Каркас** — `cmd/bot/`, конфиг, polling, sqlite-обвязка, персист
   `update_id`, `setMyCommands`, `/help`. Готово = бот отвечает в личке и
   переживает рестарт без дублей.
2. **Привязка** — `link_codes` + две ручки + кнопка в вебе; `/start <code>`,
   `/link`, `/unlink`, обработка 401. Готово = аккаунт привязывается тапом.
3. **MCP per-user + `/today`** — Bearer из sqlite, свой RoundTripper.
   Готово = каждый привязанный видит свою агенду.
4. **LLM-цикл** — конвертация схем, агентный цикл, история, замок на чат,
   лимиты, typing. Параллельно на сервере — `parseDue` пошире. Готово =
   «добавь молоко в пятницу» создаёт задачу с правильной датой у правильного
   юзера.
5. **Деплой MVP** — `Dockerfile.bot`, сервис `tobedone-bot` в `/opt/traefik`
   compose (без traefik-лейблов), volume под sqlite, README. Дальше — итерации
   поверх живого бота.
6. **Расписания** — планировщик + `/digest`, `/evening`, `/review`, `/tz`;
   на сервере — `done_since`. Готово = в пятницу вечером пришёл обзор рабочей
   доски, в воскресенье — личной.
7. **Напоминания** — `structuredContent` в тулзах + цикл напоминаний +
   `/remind`. Готово = задача с due 18:00 пингует в 18:00 и не пингует дважды.
8. **Хозяйство** — `/stats`, алерты капов, метрики в логе.

## Потом (v2)

- Inline-кнопки «✓» и «⏭ завтра» под строками дайджеста и обзоров —
  разбор утра в пару тапов без LLM (structuredContent к этому моменту уже
  будет).
- Групповой режим: бот в группе + общая доска (шаринг уже есть в
  `board_members`) — общий дайджест команды.
- Голосовые: telegram voice → STT → тот же цикл.
- Настройка «за сколько минут напоминать», тихие часы.
- Выбор модели/провайдера per-user (кто хочет — свой ключ).

## Риски

- **Публичность = расходы**: незалинкованные не тратят LLM вообще, у остальных
  дневной кап + глобальный стоп-кран. При deepseek-chat активный юзер — центы
  в месяц; расписания и напоминания LLM не трогают вовсе.
- **Приватность**: тексты задач улетают в LLM-провайдера (китайского). В
  `/help` честно написать, какая модель используется.
- **Бот хранит токены юзеров** — скоуп токена ограничен tobedone, отзыв в один
  клик из веба; sqlite в volume с правами 0600.
- **Дешёвая LLM путается в tool-вызовах** — страховка на сервере: мало
  инструментов, плоские аргументы, ошибки-подсказки; кап итераций; лог.
- **TZ-зоопарк**: у каждого юзера свой `/tz`, все расписания и «сегодня»
  считаются в нём; серверный `today_agenda` всегда зовём с явной датой.
